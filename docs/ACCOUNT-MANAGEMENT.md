# 账号删除与批量导出

账号卡片右上角提供勾选框和「删除账号」菜单。账号池工具条可全选当前筛选、导出所选、批量删除和取消选择。平台、地区、搜索条件改变时，隐藏账号会自动取消选择，避免误操作。

## 删除范围

- WorkBuddy-Api：仅从自身反代账号池移除账号引用，同时移除该账号的积分/限额/签到状态和旅行任务选择；原始 WorkBuddy Switch 账号库、客户端登录及历史统计保留。
- AgentDock 的 WorkBuddy：仅从 AgentDock 的 WorkBuddy 账号池移除，原始 Switch 账号库和客户端登录保留。两个项目独立维护账号池，删除不会自动传播到另一应用。
- AgentDock 的 Qoder、Trae：从对应本地账号库移除记录；客户端当前登录保持不变。需要恢复时可导入事先导出的 JSON。

删除前会显示账号数量、名称与实际范围，必须确认。删除后不再参与新一轮请求调度与定时任务；已经开始的请求/任务可继续结束。历史请求与统计记录保留。

WorkBuddy 批量删除先验证所有账号，持久化成功后才发布内存状态；缺失账号或写盘失败时不删除本批次。AgentDock 跨平台批量删除逐账号返回结果，成功项移除，失败项保留并提示，便于重试。

## 导出与恢复

单个与批量导出均保留平台、地区、完整登录凭据及备注，使用 AgentDock 的 `agentdock-account` / `agentdock-accounts` JSON 格式，可在 AgentDock「导入 JSON」中恢复。WorkBuddy Switch 来源记录按 ID、UID 和地区共同核对，避免导出身份已变化的记录；缺失凭据或账号时整次导出失败，不静默跳过。

文件默认保存到「下载」目录（系统未提供时回退用户主目录），文件名包含时间与随机标识，Unix 上新建文件权限为 `0600`。导出文件包含明文登录凭据，请妥善保管，不要公开分享。导出只读取本地来源，不发起生产 API 请求。

实现遵循 KISS/DRY：两边共享相同的选择范围函数和 WorkBuddy 导出模块；后端复用既有持久化流程，不引入额外依赖或后台删除服务。
