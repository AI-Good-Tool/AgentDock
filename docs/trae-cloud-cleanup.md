# Trae 云端会话自动清理

Trae 反代固定使用 Remote 云端会话，并默认自动清理。本地运行实例和本地会话模式不提供配置开关或界面入口；跨端轮询、模型选择和客户端工具桥接保持原有行为。

每次创建会话取得 ID 后，立即在独立加密队列中记录本网关对该会话的归属。正常完成后删除该会话；请求失败或取消时，先尝试停止未完成的任务，再删除会话。创建请求独立于客户端取消信号，尽量取得上游返回的会话 ID，以便随后清理。

删除使用同一账号的认证信息，仅对该次创建返回的会话 ID 发出 DELETE。204、404 或业务码 0 记为成功；其他错误最多尝试两次，401/403 不重试。清理失败不会覆盖模型回答或原请求错误，只记录脱敏状态并保留待办。应用启动后及每 5 分钟补清理失败或中断的待办，跳过当前活动会话。

请求详情显示本次清理结果，运行日志记录清理失败；不保存会话正文、模型回答或认证头。补清理队列使用现有账号库密钥加密，独立保存在 remote-cleanup.enc，成功后移除待办。队列写入和单个会话使用跨进程文件锁；另一个应用实例不会清理仍在运行的会话，签到任务写账号库也不会覆盖清理记录。不读取云端会话列表，不批量删除旧会话或用户手动创建的会话；旧版本留下、没有本网关归属记录的会话不会自动处理。

清理属于尽力执行：上游长时间不可达、账号被移除、创建响应丢失导致未取得 ID，或进程在保存归属前退出时，无法保证云端会话立即消失。应用退出期间不能补清理，重新打开后会继续处理已保存的待办。
